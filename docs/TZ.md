# Техническое задание
## Лабораторная работа №1 «Умные указатели»

Курс «Информатика (организация и поиск данных)», 3 семестр, НИЯУ МИФИ.

## 1. Назначение системы

Система - библиотека шаблонных классов «умных указателей» на C++, которые автоматически
управляют динамической памятью: освобождают объект, когда он больше никому не нужен, и тем
самым исключают утечки памяти, двойное удаление и висячие указатели.

В состав системы также входят:
- контейнер, построенный на умных указателях (проверка их работы на практике);
- функциональные тесты;
- нагрузочные тесты со сравнением с сырыми указателями и стандартной библиотекой (STL);
- средства проверки отсутствия утечек памяти.

Выбранный вариант ТЗ - **№3, децентрализованное хранение (вариант 2)**: реализуются
`UnqPtr<T>` и `ShrdPtr<T>`, подсчёт ссылок ведётся только средствами `ShrdPtr` через поле
`size_t* referenceCount`, без дополнительных объектов-хранилищ.

## 2. Сущности

### 2.1. Основные сущности (библиотека)

| Сущность | Что это | Ответственность |
|---|---|---|
| **Управляемый объект** `T` | любой объект пользователя, созданный в куче (`new T`) | хранит данные; сам не знает, что им управляет умный указатель |
| **Управляемый массив** `T[]` | массив, созданный через `new T[n]` | то же для массива; удаляется только через `delete[]` |
| **`UnqPtr<T>`** | «ведущий» указатель (master pointer), аналог `std::unique_ptr` | единолично владеет объектом и удаляет его при своём уничтожении |
| **`UnqPtr<T[]>`** | то же для массива | владеет массивом, даёт доступ по индексу, удаляет через `delete[]` |
| **`ShrdPtr<T>`** | «дескриптор» (handler), аналог `std::shared_ptr` | совместно с другими `ShrdPtr` владеет объектом; объект удаляет последний владелец |
| **`ShrdPtr<T[]>`** | то же для массива | совместное владение массивом |
| **Счётчик ссылок** `size_t* referenceCount` | число в куче, общее для всех `ShrdPtr` одного объекта | хранит количество текущих владельцев |
| **Фабрики** `MakeUnq`, `MakeShrd` | функции-шаблоны | создают объект/массив и сразу отдают его во владение указателю |
| **`DynamicArray<T>`** | динамический массив (упрощённый `ArraySequence`) | хранит элементы; память массива принадлежит `UnqPtr<T[]>` |

### 2.2. Вспомогательные сущности (проверка и измерения)

| Сущность | Назначение |
|---|---|
| **`Tracked`**, **`TrackedDerived`**, **`Unrelated`** | тестовые классы: `Tracked` считает созданные и удалённые экземпляры; `TrackedDerived` - его наследник (проверка подтипизации); `Unrelated` - несвязанный тип (проверка запрета) |
| **`LeakCheckedTest`** | база тестов: после каждого теста проверяет, что созданных объектов столько же, сколько удалённых |
| **Сценарий** и **вариант** замера | что измеряется (например, «копирование указателя») и чем (сырой указатель / наш / STL) |
| **`Measurement`** | результат замера: суммарное время и время одной операции |
| **`AllocationCounter`** | счётчик выделений памяти (через замену глобального `operator new`) |
| **`LeakDemo`** | программа с намеренной утечкой - контроль, что инструменты проверки её находят |

## 3. Связи между сущностями

```
                      владеет 1 : 1
   UnqPtr<T> ─────────────────────────────▶  объект T
       │
       │ передача владения (std::move)
       ▼
   ShrdPtr<T> ── N : 1 ── владеют ────────▶  объект T
   ShrdPtr<T> ── N : 1 ── разделяют ──────▶  счётчик referenceCount (= N)

   ShrdPtr<Derived> ──── приводится к ────▶  ShrdPtr<Base>     (если Derived наследует Base)
   UnqPtr<Derived>  ──── приводится к ────▶  UnqPtr<Base>

   DynamicArray<T> ◆──── содержит 1 ──────▶  UnqPtr<T[]>  ──владеет──▶  массив T[]

   MakeUnq / MakeShrd ── создают ─────────▶  объект + указатель-владелец
```

| Связь | Кратность | Смысл |
|---|---|---|
| `UnqPtr` → объект | 1 : 1 | **исключительное владение.** На объект указывает ровно один `UnqPtr`; копирование запрещено, владение можно только передать перемещением. При уничтожении `UnqPtr` объект удаляется |
| `ShrdPtr` → объект | N : 1 | **разделяемое владение.** Несколько `ShrdPtr` указывают на один объект; объект живёт, пока жив хотя бы один из них |
| `ShrdPtr` → счётчик | N : 1 | все владельцы одного объекта разделяют один счётчик; его значение = N. Копирование `ShrdPtr` увеличивает счётчик, уничтожение - уменьшает; при 0 удаляются объект и счётчик |
| `UnqPtr` → `ShrdPtr` | передача | `ShrdPtr` может забрать объект у `UnqPtr` (`std::move`); после этого `UnqPtr` пуст. Обратная передача невозможна (объект может быть разделён) |
| `X<Derived>` → `X<Base>` | подтипизация | указатель на наследника можно присвоить указателю на базовый класс, как и для сырых указателей. Для несвязанных типов и для массивов - запрещено (ошибка компиляции) |
| `DynamicArray` → `UnqPtr<T[]>` | композиция 1 : 1 | контейнер не освобождает память сам - это делает поле `UnqPtr<T[]>` |
| `DynamicArray<ShrdPtr<T>>` → объект | хранение ссылок | контейнер может хранить разделяемые указатели; копирование контейнера увеличивает счётчики |
| Тесты, бенчмарк → библиотека | использование | проверяют корректность и измеряют производительность, не меняя библиотеку |

## 4. Функциональные требования

### 4.1. `UnqPtr<T>` и `UnqPtr<T[]>`

| № | Требование |
|---|---|
| ФТ-1 | Создание пустого указателя (по умолчанию и из `nullptr`) и указателя, владеющего объектом, созданным через `new` |
| ФТ-2 | Удаление объекта при уничтожении указателя: `delete` для `UnqPtr<T>`, `delete[]` для `UnqPtr<T[]>` |
| ФТ-3 | Запрет копирования (ошибка компиляции); передача владения только перемещением; источник после перемещения пуст |
| ФТ-4 | Доступ к объекту: `*`, `->` для `UnqPtr<T>`; `[]` для `UnqPtr<T[]>`; `Get()`; проверка на пустоту `operator bool` |
| ФТ-5 | Управление владением: `Release()` - отказаться от владения без удаления; `Reset(p)` - удалить текущий объект и взять новый; `Swap` |
| ФТ-6 | Присваивание перемещением, в том числе самому себе, не приводит к потере объекта; `Reset` тем же указателем не удаляет объект |
| ФТ-7 | Фабрики `MakeUnq<T>(args...)` и `MakeUnq<T[]>(n)` (элементы массива инициализируются значением по умолчанию) |

### 4.2. `ShrdPtr<T>` и `ShrdPtr<T[]>`

| № | Требование |
|---|---|
| ФТ-8 | Создание пустого указателя и указателя, владеющего объектом; у пустого указателя счётчик не выделяется, `UseCount() == 0` |
| ФТ-9 | Копирование разделяет объект и увеличивает счётчик; уничтожение копии уменьшает счётчик; объект удаляется последним владельцем |
| ФТ-10 | Перемещение передаёт владение без изменения счётчика; источник становится пустым |
| ФТ-11 | Присваивание (копированием и перемещением) освобождает прежний объект, если владелец был последним |
| ФТ-12 | **Присваивание самому себе** (`p = p`, в том числе при счётчике 1) и присваивание между владельцами одного объекта не меняют счётчик и не удаляют объект |
| ФТ-13 | Создание из `UnqPtr` перемещением (передача владения) |
| ФТ-14 | Доступ: `*`, `->` / `[]`, `Get()`, `UseCount()`, `operator bool`, сравнение `==`, `!=` (между указателями и с `nullptr`) |
| ФТ-15 | `Reset()`, `Reset(p)`, `Swap`; фабрики `MakeShrd<T>(args...)`, `MakeShrd<T[]>(n)` |

### 4.3. Подтипизация

| № | Требование |
|---|---|
| ФТ-16 | Если `Derived` наследует `Base`: `ShrdPtr<Base>` создаётся и присваивается из `ShrdPtr<Derived>` (копированием и перемещением), `UnqPtr<Base>` - из `UnqPtr<Derived>` (перемещением), `ShrdPtr<Base>` - из `UnqPtr<Derived>`. Счётчик общий, вызовы виртуальных методов идут в `Derived` |
| ФТ-17 | Для несвязанных типов и в обратную сторону (`Base` → `Derived`) такие операции **не компилируются** |
| ФТ-18 | Для массивов подтипизация запрещена: `UnqPtr<Base[]>` нельзя получить из `Derived*` или `UnqPtr<Derived[]>` |

### 4.4. Обработка некорректных действий

| № | Требование |
|---|---|
| ФТ-19 | Разыменование или индексация пустого указателя бросает исключение `std::logic_error` |
| ФТ-20 | Если не удалось выделить память под счётчик, объект, переданный в `ShrdPtr`, удаляется и исключение передаётся вызывающему (утечки нет); при создании из `UnqPtr` объект остаётся у `UnqPtr` |

### 4.5. Контейнер `DynamicArray<T>`

| № | Требование |
|---|---|
| ФТ-21 | Создание пустого и заданного размера; `Get`, `Set`, `[]`, `GetSize`, `Append` (рост ёмкости удвоением), `Resize` |
| ФТ-22 | Обращение по индексу вне диапазона бросает `std::out_of_range` |
| ФТ-23 | Копирование глубокое; перемещение; присваивание самому себе безопасно; `Append` собственного элемента при перевыделении работает корректно |
| ФТ-24 | При уменьшении размера ресурсы удалённых элементов освобождаются сразу (для `ShrdPtr` - уменьшаются счётчики) |

### 4.6. Тестирование и измерения

| № | Требование |
|---|---|
| ФТ-25 | Функциональные тесты на все требования ФТ-1…ФТ-24, включая граничные случаи; проверка отсутствия утечек после каждого теста (`created == destroyed`) |
| ФТ-26 | Нагрузочные тесты: время (суммарное и на операцию) и память для сырого указателя, наших указателей и STL; сценарии - создание/удаление объектов и массивов, копирование, передача по значению |
| ФТ-27 | Объёмы - от единиц до 10⁸ операций (параметр `--max`) |
| ФТ-28 | Результаты - в табличном виде (консоль, CSV) и в графическом (графики PNG) |
| ФТ-29 | Проверка отсутствия утечек и ошибок памяти valgrind и санитайзерами (ASan, UBSan) с контрольной программой, содержащей намеренную утечку |

## 5. Нефункциональные требования

| № | Категория | Требование |
|---|---|---|
| НФТ-1 | Ограничения реализации | Стандартные умные указатели (`<memory>`) в библиотеке не используются - только в нагрузочных тестах для сравнения. `weak_ptr` не реализуется |
| НФТ-2 | Шаблонность | Все классы библиотеки - шаблоны; определены целиком в заголовочных файлах (header-only) |
| НФТ-3 | Надёжность | Нет утечек памяти, двойного удаления, обращений к освобождённой памяти и неопределённого поведения - подтверждается valgrind и ASan/UBSan |
| НФТ-4 | Производительность | `UnqPtr` не медленнее сырого указателя с ручным `delete`. Операции со счётчиком `ShrdPtr` (копирование, передача по значению) быстрее `std::shared_ptr`; создание - не медленнее `std::shared_ptr(new T)` |
| НФТ-5 | Память | `UnqPtr` занимает столько же, сколько сырой указатель; `ShrdPtr` на объект - не больше, чем `std::shared_ptr` |
| НФТ-6 | Сложность | Все операции указателей - O(1); `DynamicArray::Append` - амортизированно O(1) |
| НФТ-7 | Безопасность при исключениях | Операции перемещения, обмена, деструкторы - `noexcept`; при исключении состояние объектов остаётся корректным, утечек нет |
| НФТ-8 | Переносимость | Стандартный C++17 без расширений компилятора; сборка CMake ≥ 3.14; ОС Windows (MinGW GCC) и Linux (GCC). Сборка без предупреждений при `-Wall -Wextra -Wpedantic` |
| НФТ-9 | Качество кода | Стиль по правилам Голуба: отступ 4 пробела, скобки на отдельных строках, английские имена, именованные константы, функции с одной задачей |
| НФТ-10 | Интерфейс | Консольный: тесты и бенчмарк запускаются из командной строки или CLion; бенчмарк проверяет параметры и выводит справку при ошибке. Графический интерфейс не требуется |
| НФТ-11 | Документация | README с описанием сборки, запуска и результатов; комментарии в коде объясняют неочевидные решения |

## 6. Ограничения и допущения

- **Однопоточность.** Счётчик `ShrdPtr` не атомарный: копировать один `ShrdPtr` из нескольких
  потоков одновременно нельзя. Это сознательная плата за скорость (НФТ-4).
- **Циклические ссылки** (`A` хранит `ShrdPtr` на `B`, а `B` на `A`) приводят к утечке:
  для их разрыва нужен `weak_ptr`, который по условию не реализуется.
- Объект, переданный в указатель, должен быть создан через `new` (массив - через `new[]`),
  и один сырой указатель нельзя отдавать двум разным `ShrdPtr`.
- Удаление наследника через указатель на базовый класс корректно, только если у базового
  класса виртуальный деструктор.

## 7. Критерии приёмки

1. Проект собирается без ошибок и предупреждений (Debug и Release).
2. Все функциональные тесты проходят.
3. valgrind: `All heap blocks were freed`, `ERROR SUMMARY: 0 errors`; ASan + UBSan - без
   сообщений; контрольная утечка в `LeakDemo` обнаружена.
4. Нагрузочные тесты выполнены до N = 10⁸, результаты представлены таблицами и графиками,
   выводы о сравнении с STL сделаны.
